This is a minor release of WebSharper 10.1.

## Fixes

* #1687 F# projects using type providers, such as `Zanaptak.TypedCssClasses`, failed to build intermittently with type provider errors (`FS0039` for a provided member that exists, `FS3021`, `FS3033`) since 10.1.8: the assembly was emitted (#1587) while WebSharper type checked the project, and both type checks called into the type provider at the same time, corrupting its caches that are not thread-safe. With a type provider among the references, the assembly is now emitted only after the WebSharper type check, still overlapping with the translation.
* #1689 Fixed client-side `WebSharper.Json` treating the backing field of a record's `static member val` (for example `Zero@`) as a mandatory instance field: the decoder rejected JSON the server produced and the encoder read a field that is not there. Static fields are no longer part of an F# record's shape in WebSharper metadata, also for its JavaScript constructor and field accessors. Libraries defining such records need to be recompiled.
