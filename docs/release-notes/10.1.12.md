This is a minor release of WebSharper 10.1.

## Performance

* #1697 Emitted the .NET assembly in parallel with the WebSharper type check again for projects using the WebSharper.UI templating type provider, which is almost every WebSharper.UI application; the fix for #1687 below would otherwise delay it until after the type check whenever a type provider is referenced. Type providers that are safe to run from two type checks at the same time can say so: the compiler recognizes `WebSharper.ThreadSafeTypeProviderAttribute` on the type provider's assembly by its full name, so a type provider can declare its own copy instead of referencing WebSharper. WebSharper.UI marks its templating type provider.
  * The `WebSharperThreadSafeTypeProviders` MSBuild property (`threadSafeTypeProviders` in `wsconfig.json`, `--threadsafetypeprovider:<name>`) treats other type providers as thread-safe, by assembly name.
  * `WebSharperSerializeTypeProviders=true` (`serializeTypeProviders`, `--serializetypeproviders+`) delays the assembly whenever a type provider is referenced, for a marked type provider that turns out not to be thread-safe.
  * With detailed build output (`-v:d`), the compiler names the type providers that made it wait.

## Fixes

* #1687 F# projects using type providers, such as `Zanaptak.TypedCssClasses`, failed to build intermittently with type provider errors (`FS0039` for a provided member that exists, `FS3021`, `FS3033`) since 10.1.8: the assembly was emitted (#1587) while WebSharper type checked the project, and both type checks called into the type provider at the same time, corrupting its caches that are not thread-safe. With a type provider among the references, the assembly is now emitted only after the WebSharper type check, still overlapping with the translation.
* #1689 Fixed client-side `WebSharper.Json` treating the backing field of a record's `static member val` (for example `Zero@`) as a mandatory instance field: the decoder rejected JSON the server produced and the encoder read a field that is not there. Static fields are no longer part of an F# record's shape in WebSharper metadata, also for its JavaScript constructor and field accessors. Libraries defining such records need to be recompiled.
