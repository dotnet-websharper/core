This is a preview release of WebSharper 11.0.

## Features

* #1279 Extended the JavaScript parser for inline code (`Inline`, `Direct`, `JS.Inline`, WIG inlines) to ES2022:
  * `let` and `const` declarations, `for...of`, `for (let/const x in/of ...)`, labeled statements, and function declarations inside blocks.
  * Default and rest parameters, `async` functions and arrow functions with `await`, generator functions with `yield` and `yield*`, and the `async` and generator forms of object methods.
  * Template literals, including tagged templates.
  * Spread in calls, `new` and array literals; spread, shorthand properties, methods, getters and setters, and computed property names in object literals. Object spread and computed names were translated to `Object.assign` and property assignments.
  * Optional chaining (`a?.b`, `a?.[i]`, `f?.(x)`, with `this` kept for `o.m?.(x)`), `??`, and the `??=`, `&&=`, `||=` and `**=` assignment operators.
  * Classes, modules and destructuring remained unsupported in inline code.
* #1279 Added WebSharper AST forms for generator and async functions (`FuncWithKind`, and a `FuncKind` on class methods), `yield` expressions, spread, template strings, optional chaining and `for...of` loops, used by the inline parser and available to macros and generators.
* #788 Filled in the default values of omitted optional arguments when calling a delegate, which covered delegate types with default parameter values and C# 12 lambdas with default parameters (#1367).

* #542 Translated C# iterator methods to JavaScript generator functions. Disposing an enumerator early, for example after `Take`, now runs the pending `finally` blocks of the iterator, as in .NET. Iterators containing `goto` still compiled to a state machine.
* #1279 Translated F# sequence expressions (`seq { ... }`) to a single generator function instead of nested `Seq.delay`, `Seq.append`, `Seq.collect` and similar calls. `for`, `while`, `try/finally`, `use`, `if` and `let` became the corresponding statements, and other sub-sequences were enumerated with `yield*`.
* #1279 Translated F# list and array comprehensions (`[ ... ]`, `[| ... |]`) to loops building the result directly, instead of building a sequence first: arrays with `push`, lists by appending cons cells from the head.
* #1544 Sequences created from C# iterators and F# sequence expressions were also JavaScript iterables (`for...of`, spread).
* Added the `Iterate` and `Iter` runtime functions: `Iterate(f)` made an `IEnumerable` from a generator function, `Iter(s)` made a JavaScript iterable from any .NET sequence.
* #1279 Translated C# async methods, async lambdas and async local functions to JavaScript async functions instead of a state machine. Tasks became thenable, so JavaScript `await` works on them, and the method returns the task of the async function. Continuations after `await` always run asynchronously, also when the awaited task was already completed. Methods with `goto` and async iterators still compiled to a state machine.
* #1279 Translated F# task expressions (`task { ... }`) to JavaScript async functions: `let!`, `do!` and `return!` on tasks became `await`, and `for`, `while`, `try/with`, `try/finally`, `use`, `if` and `let` the corresponding statements. Other parts, for example `let!` on an F# `Async` or `and!`, ran as a task of their own that was awaited.
* #1279 Awaiting a failed task threw the original exception instead of an `AggregateException`, as in .NET, and awaiting a canceled task threw a `TaskCanceledException`. `Task.Exception` of a failed async method was an `AggregateException`.
* #699 Supported C# structs with fields that can change: their values were copied when assigned, passed as arguments, returned, boxed, or added to collections, like in .NET. Nested struct fields were copied too, and the elements of `new S[n]` were separate values. Value tuples were copied when a variable of the tuple changed its elements in place. `readonly` structs and structs with only `readonly` fields were not copied. F# structs with mutable fields remained unsupported.
* #1237 Supported C# record structs, including positional ones.
* #1223 Supported C# indices and ranges: `^n`, `a..b`, `System.Index` and `System.Range`, indexing arrays, strings and lists with an `Index` (`a[^1]`, also as an assignment target and in object initializers), and ranges of arrays and strings (`a[1..^1]`). An `Index` was a number in JavaScript (`~n` for `^n`, as .NET stores it), a `Range` an array of two indices.
* #1239 Filled in the values of omitted arguments for parameters with `CallerArgumentExpression`, `CallerMemberName`, `CallerLineNumber` and `CallerFilePath` in C# method and constructor calls.
* #787 Supported format strings in C# interpolated strings for `DateTime` and `Guid` values, for example `$"{d:yyyy-MM-dd}"`, using their `ToString(format)` implementation.
* Called the `string` overload for C# methods taking an interpolated string handler, such as `StringBuilder.Append($"...")`, which previously failed to compile.

## Output quality

* #1279 Translated C# `foreach` over arrays to `for...of`.

* #816 Removed the immediately invoked functions wrapped around loop bodies that captured a loop variable in a closure, in both C# and F#. Output already declared variables with `let`/`const`, which gave a new binding on each iteration. A captured F# loop variable was copied to a `const` at the start of the loop body. C# methods that became a state machine (iterators, async methods, remaining `goto`s) still used the wrapper.
* #542 Translated a C# `goto` that jumped forward out of nested statements to a later statement of an enclosing block as a `break` out of a labeled block, so such methods no longer needed a state machine. This covered the lowered C# 15 labeled `break` and `continue` too.
* #816 Declared variables with their first value (`let x = v` instead of `let x; x = v`), wrote `const` for every variable that was not reassigned, and inlined more immediately applied functions: the optimizer rule that prevented it was needed only for function-scoped `var`.
* #1279 Let the optimizer see through the type casts added for TypeScript output, which had prevented inlining of variables and functions and some other optimizations. The minified size of the test bundle decreased by about 0.9%.
* #1279 Added a cleanup step after the optimizer for variables it left behind: compiler-generated copies of other variables, temporaries used once in the next statement (fluent call chains are written as one chain again), temporaries that were assigned but never read, and declarations without a value followed by their first assignment. F# ref cells that do not leave the function became plain `let` variables. Expression statements without effects (like `else null;` and the `void 0` left of `(void 0, task)` for F# `task { }`) were removed. Constant C# field initializers, like default values, no longer moved to temporary variables before `super()`. The minified test bundle decreased by about 1.7% (2.9% gzipped).
* #1279 Inlined F# members called without their `[<Optional>]` arguments use the default value directly, instead of a variable checked against `undefined`. F# methods with `[<Optional; DefaultParameterValue>]` parameters got JavaScript default parameters. The optimizer folded comparisons of literals with `undefined` and `null`.
* #1279 Wrote C# optional parameters as JavaScript default parameters, for example `Opt(x = 0, s = "a")`.
* Added `tests/Scripts/OutputSize.mjs` to measure the size of the test bundles.

## Fixes

* #1279 Fixed variables that were assigned without being declared (written as `MISSINGVARname`, a `ReferenceError` when run), for example in inlined F# members called without their `[<Optional>]` arguments. The optimizer replaced a variable bound to `null`, or to a value used once, by its value even when it was assigned later, and replaced a variable copying another one even when it was assigned, which could also change the other variable.
* #1279 Added a compile error for variables that are used but not declared after translation. This is always a compiler bug, the code at that place calls the `CompileError` runtime function.
* #1279 Translation errors in projects compiled with `WarnOnly` (or `WebSharperErrorsAsWarnings`) produced a `"$$ERROR$$"` string in the output, which could make code pass silently. Such places now call the `CompileError` runtime function with the error message, which throws when the code runs.
* #1279 Fixed C# enum operators (`==`, `!=`, `<`, `+`, `-` and the like) and `++`/`--` on enum values, which were reported as numeric macro errors.
* #1279 Fixed lifted comparisons of nullable values: `!=` was false when only one side was null, and `<=` and `>=` were true when both sides were null.
* #1279 Translated delegate subtraction (`-=`, `Delegate.Remove`) on fields and variables, for example in custom event remove accessors. `Delegate.Remove` and `RemoveAll` followed .NET semantics for multicast delegates and null values.
* #1279 Ran C# instance field initializers before the base constructor call, as .NET does.
* #542 Fixed C# loops with captured variables that contained `break` or `goto` (previously "Break outside of loop" or an invalid `Goto` form), and the return value of a `return` inside such loops in iterators and async methods.
* Fixed `??` next to `&&` or `||` in written JavaScript, which needs parentheses.
* #1279 Fixed `Seq.concat` (and so `Seq.collect` and LINQ `SelectMany`) disposing the outer enumerator when an inner sequence ended.
* #1279 Fixed `function` expressions in inline JavaScript, which were written as arrow functions, so `this` and `arguments` inside them referred to the enclosing scope. Getters and setters of inline object literals, which were written as plain fields, now work too.
* #1279 Fixed equality of C# records, which compared each member of a record with itself, so records of the same type were always equal. Members are compared with `Equals`, like `EqualityComparer<T>.Default` in .NET.
* #1279 Fixed the copy constructor of C# records (used by `with` and `<Clone>$`), which copied only the positional properties.
* #1294 Fixed `default(S)` of a C# struct with a parameterless constructor, which ran the constructor; it now gives the struct with the default field values.
* Fixed C# `new T[n]` without an initializer, which created an empty array instead of `n` default values.
* Fixed C# nested member initializers (`new C { Items = { [0] = 1 } }`), which failed with a null reference error.
* Fixed C# `x is var (a, b)` patterns on types with a `Deconstruct` method, which read the value as a tuple; they now call `Deconstruct`, and are false for `null`.

## Breaking changes

* #1279 Changed the metadata format version to `11.0-preview.2`, libraries had to be recompiled.
* #1279 Added a `FuncKind` field to `Syntax.Lambda`, `Syntax.Function` and `Syntax.Method` in `WebSharper.Core.JavaScript`, so generators returning JavaScript syntax had to pass `Syntax.Normal`. Added `FuncKind` to `ClassMethodInfo` and `DefaultValue` to `Syntax.Id`.
* #1279 Made `const`, `class` and `super` reserved words in inline JavaScript.
