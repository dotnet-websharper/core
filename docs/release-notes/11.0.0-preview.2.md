This is a preview release of WebSharper 11.0.

## Features

* #1618 Made the `WebSharper.FSharp` and `WebSharper.CSharp` packages much smaller (about 15 MB and 12 MB instead of 128 MB and 88 MB) by including only the portable compiler, and added the ReadyToRun compilers as the optional `WebSharper.FSharp.Booster` and `WebSharper.CSharp.Booster` .NET tools for Windows, Linux, and macOS on x64 and arm64. Install them for the full compilation speed: the build used a tool when it was installed at exactly the WebSharper version the project referenced, and the portable compiler otherwise.
  * Added `dotnet ws compiler status` and `dotnet ws compiler sync` to the latest `dotnet ws` (`dotnet tool update -g dotnet-ws`) to manage the tools. `status` showed which compiler each project built with, and `sync --local` added the tools at the project's WebSharper version to the repository's tool manifest (`--global` installed them globally). Run `dotnet ws compiler sync` again after updating WebSharper. Installing the tools required .NET SDK 10 or newer.
  * Added warning WSB9101 for a tool manifest listing a Booster tool of another WebSharper version, and WSB9102 for a listed tool that was not restored. `WebSharperUseBoosterTool=false` turned the tool lookup off.
  * Made the booster (wsfscservice) also run with the portable compiler, so F# builds used it on every platform.
* Made the WebSharper booster (`wsfscservice`) answer questions of AI agents about the projects it compiled, as a [Model Context Protocol](https://modelcontextprotocol.io) server: `wsfscservice --mcp` runs a stdio MCP server that forwards tool calls to the running booster of the same installation. The tools gave the diagnostics of the last compilation, F# signatures of types and members of the project and its references, symbol search, usages, file signatures, how WebSharper translates a type or member to JavaScript (or that it can't be used in client-side code), the project's RPC methods, and compiling a project again like `dotnet ws build`. See [BoosterMCP.md](../BoosterMCP.md).
  * `get_signature` and `get_js_translation` took several names at once (`names`), so an agent needed one call for all the APIs it was about to use.
  * Name lookups dropped a wrong namespace, found extension members and template members, showed deprecations, and suggested close names for typos. `get_signature` on a namespace listed its types and modules, and `get_diagnostics` showed the source line of the first errors with the signatures of the functions and values used on it, and hints for common errors.
  * The booster kept the last compilation of the 10 most recently compiled projects for these tools, `WebSharperAgentProjects` (an environment variable of the booster) set how many. `WebSharperMcpLog` logged the tool calls of `wsfscservice --mcp` to a file.
  * Other packages could add tools with an `IAgentExtension` assembly, given to the booster by the `WebSharperAgentExtensions` MSBuild property and to `wsfscservice --mcp` by `--extension` or the `WebSharperAgentExtensions` environment variable.
  * The booster kept statistics on the machine: the waiting and processing time of every message it handled, compilation stages, errors and warnings by code, and for agent tools, core's and extensions' alike, their durations, outcomes and answer sizes, MCP requests end to end, clients, sessions and whether agents followed the pointers in answers. `dotnet ws stats` showed them. Extensions implementing `IAgentExtensionWithHost` recorded their own through `IAgentHost.Stats`. They held no source, symbol names, paths or project names. See [BoosterMCP.md](../BoosterMCP.md#statistics).
* Added a booster for C# projects, `wscscservice`, that answers AI agents about the WebSharper C# projects built on the machine, as an MCP server: `wscscservice --mcp`. It does not compile: `wscsc` compiled as before, then reported each compilation to the booster of its installation (starting it when none ran), with the printed output and the paths of the assembly and its references. The booster answered from these reports and the WebSharper metadata of the project and its references, so it needed no C# compiler. See [BoosterMCP.md](../BoosterMCP.md#c-projects).
  * Its tools were `list_projects`, `get_diagnostics` (WebSharper errors and warnings, with the source line of the first errors and hints), `get_js_translation` (also for C# type keywords and partial names, several names at once), `search_symbols` (types and members translated by WebSharper) and `list_rpc_methods`.
  * `WebSharperStandalone=True`, now passed to `wscsc` by the C# targets, or the `WebSharperBuildService` environment variable set to `false`, kept a build from reporting to the booster. Builds stopped by C# compiler errors never reached `wscsc`, so the booster did not see them.
  * The formatting of WebSharper translations moved to `WebSharper.Compiler.AgentTranslation`, shared by both boosters; the F# booster's `AgentTools` kept its names.
  * The C# booster loaded agent extensions like the F# booster: assemblies implementing `WebSharper.CSharp.Service.AgentTools.IAgentExtension`, from the `WebSharperAgentExtensions` MSBuild property, which the C# targets passed to `wscsc` (`--agentextension:`) and `wscsc` reported with each compilation, and for `wscscservice --mcp` from `--extension` or the `WebSharperAgentExtensions` environment variable.
* #1279 Extended the JavaScript parser for inline code (`Inline`, `Direct`, `JS.Inline`, WIG inlines) to ES2022:
  * `let` and `const` declarations, `for...of`, `for (let/const x in/of ...)`, labeled statements, and function declarations inside blocks.
  * Default and rest parameters, `async` functions and arrow functions with `await`, generator functions with `yield` and `yield*`, and the `async` and generator forms of object methods.
  * Template literals, including tagged templates.
  * Spread in calls, `new` and array literals; spread, shorthand properties, methods, getters and setters, and computed property names in object literals.
  * Optional chaining (`a?.b`, `a?.[i]`, `f?.(x)`), `??`, and the `??=`, `&&=`, `||=` and `**=` assignment operators.
  * Classes, modules and destructuring remained unsupported in inline code, and `const`, `class` and `super` became reserved words there.
* #542 Translated C# iterator methods to JavaScript generator functions. Disposing an enumerator early, for example after `Take`, ran the pending `finally` blocks of the iterator, as in .NET.
* #1279 Translated F# sequence expressions (`seq { ... }`) to a single generator function instead of nested `Seq.delay`, `Seq.append`, `Seq.collect` and similar calls, and F# list and array comprehensions (`[ ... ]`, `[| ... |]`) to loops building the result directly.
* #1544 Made sequences created from C# iterators and F# sequence expressions JavaScript iterables, usable with `for...of` and spread.
* #1279 Translated C# async methods, async lambdas and async local functions, and F# task expressions (`task { ... }`), to JavaScript async functions.
  * Made tasks thenable, so JavaScript `await` works on them.
  * Continuations after `await` always ran asynchronously, also when the awaited task was already completed.
  * Awaiting a failed task threw the original exception instead of an `AggregateException`, as in .NET, and awaiting a canceled task threw a `TaskCanceledException`.
* #699 Supported C# structs with fields that can change: their values were copied when assigned, passed as arguments, returned, boxed, or added to collections, as in .NET. `readonly` structs and structs with only `readonly` fields were not copied. F# structs with mutable fields remained unsupported.
* #1237 Supported C# record structs, including positional ones.
* #1223 Supported C# indices and ranges: `^n`, `a..b`, `System.Index` and `System.Range`, indexing arrays, strings and lists with an `Index` (`a[^1]`), and ranges of arrays and strings (`a[1..^1]`).
* #1239 Filled in the values of omitted arguments for parameters with `CallerArgumentExpression`, `CallerMemberName`, `CallerLineNumber` and `CallerFilePath` in C# calls.
* #788 Filled in the default values of omitted optional arguments when calling a delegate, including C# 12 lambdas with default parameters (#1367).
* #787 Supported format strings in C# interpolated strings for `DateTime` and `Guid` values, for example `$"{d:yyyy-MM-dd}"`.
* Supported C# methods taking an interpolated string handler, such as `StringBuilder.Append($"...")`, by calling their `string` overload.
* #1279 Changed `Syntax.Lambda`, `Syntax.Function` and `Syntax.Method` in `WebSharper.Core.JavaScript` and `ClassMethodInfo` in `WebSharper.Core.AST` to have a `FuncKind`, so macros and generators creating them had to pass `Normal`.

## Output quality

* #816 Wrote shorter, more readable JavaScript:
  * Declared variables with their first value and used `const` for every variable that was not reassigned.
  * Removed the immediately invoked functions around loop bodies that captured a loop variable in a closure.
  * Translated C# `foreach` over arrays to `for...of`.
  * Wrote C# optional parameters, and F# `[<Optional; DefaultParameterValue>]` parameters, as JavaScript default parameters.
  * Removed temporary variables, copies and statements without effects left by the optimizer, and turned F# ref cells that did not leave the function into plain variables.
* #542 Translated C# `goto` statements that jumped forward out of nested statements, including C# 15 labeled `break` and `continue`, without a state machine.
* #1279 Made the minified test bundle about 1.5% smaller than in preview.1 (2.3% gzipped), although it contained more tests.

## Fixes

* #1616 A `websharper.log` the compiler could not delete, for example one created by a booster that a sandboxed AI agent (such as Codex on Windows) started under another identity, failed the build. The compiler now starts the log fresh when it can, and otherwise logs to `websharper.<user>.log` in the project folder, passes that path to the booster, and names it in the WSB9002 warnings. The booster also wrote its startup and crash log to the path it was given, which it had ignored.
* #1279 Fixed variables that were assigned without being declared (written as `MISSINGVARname`, a `ReferenceError` when run), for example in inlined F# members called without their `[<Optional>]` arguments. Any remaining case is reported as a compile error.
* #1279 Translation errors in projects compiled with `WarnOnly` (or `WebSharperErrorsAsWarnings`) produced a `"$$ERROR$$"` string in the output, which could make code pass silently. Such places now throw an error with the message when they run.
* #1279 Fixed C# enum operators (`==`, `!=`, `<`, `+`, `-` and the like) and `++`/`--` on enum values, which were reported as errors.
* #1279 Fixed lifted comparisons of nullable values: `!=` was false when only one side was null, and `<=` and `>=` were true when both sides were null.
* #1279 Supported delegate subtraction (`-=`, `Delegate.Remove`) on fields and variables, for example in custom event remove accessors, following .NET semantics for multicast delegates and null values.
* #1279 Ran C# instance field initializers before the base constructor call, as .NET does.
* #542 Fixed C# loops with captured variables that contained `break` or `goto` (previously "Break outside of loop" or an invalid `Goto` form), and the return value of a `return` inside such loops in iterators and async methods.
* Fixed `??` next to `&&` or `||` in JavaScript output, which needs parentheses.
* #1279 Fixed `Seq.concat` (and so `Seq.collect` and LINQ `SelectMany`) disposing the outer enumerator when an inner sequence ended.
* #1279 Fixed `function` expressions in inline JavaScript, which were written as arrow functions, so `this` and `arguments` inside them referred to the enclosing scope, and getters and setters of inline object literals, which were written as plain fields.
* #1279 Fixed equality of C# records, which compared each member of a record with itself, so records of the same type were always equal.
* #1279 Fixed the copy constructor of C# records (used by `with`), which copied only the positional properties.
* #1629 Fixed the server-side JSON of `decimal`, `bigint`, `int64` and `uint64`, which was written and read with the server's culture. On a server whose culture uses a decimal comma (`de-DE`, `es-ES`, ...), `1234.5m` was sent as `"1234,5"`, which the client could not read, and a `"1234.5"` from the client was read as `12345`. Untyped JSON numbers (decoded as `obj`) had the same problem (`1.5` was read as `15`). They now always use the invariant culture.
* #1629 Made the error for `decimal` and `System.Numerics.Complex` in remoting or client-side JSON say that the WebSharper.MathJS package provides their client-side support.
* dotnet-websharper/ui#314 Fixed `GetHashCode` of C# records, which called itself through `Unchecked.Hash` and overflowed the stack, for example when records were put in a `HashSet`/`Dictionary` or rendered with an unkeyed `DocSeqCached`. It now hashes the members, consistently with `Equals`.
* Fixed the `EqualityContract` property of C# records, which read itself and overflowed the stack. It returns the runtime class of the record, so comparing the contracts of two records (with `ReferenceEquals` or `object.Equals`) tells whether they have the same type; `==` on `System.Type` is not supported.
* #1294 Fixed `default(S)` of a C# struct with a parameterless constructor, which ran the constructor instead of giving the default field values.
* Fixed C# `new T[n]` without an initializer, which created an empty array instead of `n` default values.
* Fixed C# nested member initializers (`new C { Items = { [0] = 1 } }`), which failed with a null reference error.
* Fixed C# `x is var (a, b)` patterns on types with a `Deconstruct` method, which read the value as a tuple; they now call `Deconstruct`, and are false for `null`.
* #1621 Fixed dead code elimination removing `Dictionary` members that were only called through `IDictionary<'K, 'V>` or `IReadOnlyDictionary<'K, 'V>`, for example on the result of `dict` or `readOnlyDict`, or through an F# member constraint such as FsToolkit.ErrorHandling's `ValueOption.tryGetValue`. Such calls failed at run time with an error like `dict(...).TryGetValue is not a function`.
* #1623 Fixed inline members with a `try`/`finally` or `try`/`with` in expression position, such as `use` in a computation expression whose builder comes from another project or library, that could lose their result: the generated JavaScript wrote it to a variable of the calling code, giving a wrong value or `MISSINGVAR`.
* #1622 Fixed F# `unit` values compiling to `null` in some places and to `undefined` in others, so structural equality treated them as different: `ignore 1 = ()` and `Ok (ignore 1) = Ok ()` were `false`. Unit values now compiled to `undefined` everywhere, so `box () = null` was `false` too, unlike on .NET.
* Fixed the booster (`wsfscservice`) failing a build without a message when it could not parse the compile options, for example after `wsconfig.json` became invalid JSON between two `dotnet ws build` runs. It sent two exit codes for the request, `-12211` and then `0`, and dropped the error. It now printed the error as `WebSharper error WS9001`, like a standalone compilation, and returned exit code 1.
* Fixed FSharp.Core collection functions throwing a plain `Exception` where .NET throws a specific type: `List`/`Seq`/`Array` `head`, `last`, `reduce`, `average`, `max`, `exactlyOne`, `zip` and `item` throw `ArgumentException`, `take`/`Seq.skip` past the end `InvalidOperationException`, `find`/`pick` `KeyNotFoundException`, array indexing `IndexOutOfRangeException` and `Array.sub` `ArgumentOutOfRangeException`. `Option.get None` throws `ArgumentException` instead of a `TypeError`.
* Fixed F# `round`, which rounded halfway values away from zero (`round 2.5 = 3.0`); it rounds to even, as `Math.Round` does. `log10` and `Math.Log10` use `Math.log10`, so `log10 1000.0` is exactly `3.0`.
* Fixed `compare` with `nan`, which said `nan` is greater than every number, so `List.sort` put it at an arbitrary place; `nan` sorts first and equals `nan`, as in .NET. `max` and `min` on floats return `nan` when either argument is `nan`, and `abs Int32.MinValue` throws `OverflowException`.
* Fixed `>>>` on `uint32`, which shifted in the sign bit (`0x80000000u >>> 31` was `-1`); `&&&`, `|||`, `^^^` and `<<<` on `uint32` keep the result unsigned.
* Fixed `int "4x2"` and the other F# conversions from string to an integer type returning `0` for invalid input; they throw `FormatException` and accept what FSharp.Core accepts (whitespace, a sign, `0x`/`0o`/`0b` literals).
* Fixed the `ArgumentException(message, paramName)` constructor, which used its arguments the other way round; the message is `message (Parameter 'paramName')` as on .NET, and `ParamName` is supported. `invalidArg` gives the same message.
* Fixed bitwise operators (`|||`, `&&&`, `^^^`, `~~~`) on F# enums declared in the project being compiled, which failed with "Could not find method for trait call".
* Fixed `Convert.ToDouble` and `Convert.ToSingle` of a `double`/`single`, which truncated the value to an integer.
* Fixed `Char.IsLetter`, `IsDigit`, `IsUpper` and `IsLower`, which only recognized ASCII characters; they use the Unicode categories.
* Fixed the `DateTime` constructor rolling invalid dates over (`DateTime(2023, 2, 29)` was March 1); it throws `ArgumentOutOfRangeException`. `DateTime.MinValue`/`MaxValue` are 0001-01-01 and 9999-12-31 (they were the limits of JavaScript dates), and `Ticks` counts from 0001-01-01 of the local time, as on .NET.
* Added `Math.DivRem`, `Convert.ToString(value, toBase)`, `Convert.ToInt32(value, fromBase)`, `Convert.ToBase64String`/`FromBase64String`, `Char.ToUpper`/`ToLower` (and the `Invariant` versions), `LanguagePrimitives.PhysicalEquality`, the F# `Failure` pattern and `sprintf "%u"`.
* Fixed F# `string` of options, bools, lists, tuples and `null`, which used JavaScript's `String`: `string (Some 1)` was `[object Object]`, `string true` was `true`, `string [1; 2; 3]` was `[object Object]`, `string (1, "a")` was `1,a` and `string (null: string)` was `null`. They now print as on .NET: `Some(1)`, `True`, `[1; 2; 3]` (at most three elements, then `; ... `), `(1, a)` and an empty string (`None` too). The format follows the static type, so nested values print correctly (`Some([1; 2])`, `[Some(1)]`); a value typed as `obj` or a generic type parameter prints `null` as an empty string and a bool as `True`/`False`.
* Fixed F# `string` and `ToString()` of enum values, which gave the number (`string Color.Green` was `2`, `string DateTime.Now.DayOfWeek` was `4`). They give the member name, `A, B` for `[<Flags>]` combinations and the number for undefined values, as on .NET and as C# already did.
* #1683 Fixed F# integer arithmetic not wrapping around like .NET: `+`, `-`, `*` and unary `-` on `int`, `uint32`, `int16`, `uint16`, `sbyte`, `byte`, `int64` and `uint64` overflowed into larger numbers (`Int32.MaxValue + 1` was `2147483648`, `255uy + 1uy` was `256`). They now wrap to the size of the type, as in C#. Also on these types: `~~~` and `<<<` on unsigned and 8/16-bit types are cut to the type, shift counts are masked as on .NET (`1uy <<< 9` is `2`, `1L <<< 65` is `2`), `uint32` division stays unsigned, and `int16`/`sbyte` `MinValue / -1` wraps.
* #1683 Fixed C# and F# `int`/`uint` multiplication losing the low bits when the product passed 2^53 (`x * x` with `x = (1 << 28) + 1` gave `536870912` instead of `536870913`): it uses `Math.imul`. A chain of `+` and `-` on these types wraps once, at the end.
* #1683 Added the F# `Checked` module: `Checked.(+)`, `(-)`, `(*)`, `(~-)` and the conversions (`Checked.int`, `Checked.byte`, ...) throw `OverflowException` instead of wrapping around.
* #1685 Fixed source maps of `spa` and bundle projects leaving out the project's own C# and F# files: the map named them by their path on the build machine (C#) or a bare file name (F#), and they were not copied next to the bundle, so the browser's developer tools could not open them (404). They are now written to `Source/<Assembly>/` like the sources of referenced assemblies, and the map points there, so you can set breakpoints in your own `.cs`/`.fs` files in the browser.
