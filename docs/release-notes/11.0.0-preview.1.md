This is a preview release of WebSharper 11.0. NuGet version `11.0.0.695-preview.1`.

Templates for .NET Core SDK: `dotnet new install WebSharper.Templates@11.0.0.695-preview.1`

## Features

* #1601 Added .NET 11 as a target framework option and made it the default for all project templates.
  * Added the .NET 11 `MemoryExtensions.Min` and `Max` span overloads, which are now selected for array extension calls.
  * Added support for `ReadOnlySpan<T>.ToArray` in collection builder methods.
* #1600 Added translation support for C# 15 collection expression arguments, union declarations and patterns, extension indexers, and labeled `break` and `continue`.
  * Added the `Enumerable.Chunk` proxy using the shared `Seq.chunkBySize` implementation.
* #1599 Added JavaScript support for FSharp.Core `partitionWith` on arrays, lists, sets, and parallel arrays, and added tests for record spreads, extension operators, and all-fields record constructors.
  * Preserved resolved F# extension operators in generic inline calls.
* #1612 Added the HTTP `QUERY` method ([RFC 10008](https://www.rfc-editor.org/rfc/rfc10008.html)) as `Http.Method.Query`, with parsing and serialization for `"QUERY"`. Endpoints can use it like other methods, for example `[<EndPoint "QUERY /search"; Json "filter">]` or `[<Method "QUERY">]`, and `Router.Fetch*`/`Router.XHR*` send it.
  * Added `UrlHelpers` request patterns for custom routers (`Router.New`), composable with the method patterns: `(|PATH|)` gives the path segments of the request URL, unescaped one by one so that `%2F` stays inside its segment (unlike `SPLIT_BY`, which splits the unescaped path); `(|PARAM|_|) name` matches a query string parameter and `(|FORM|_|) name` a form field of the body. For example `| GET & PATH ["blog"; INT id] & PARAM "page" (INT page) -> Some (Blog (id, page))`.

## Performance

* #580 Introduced a new WebSharper metadata format and serializer.
  * Reduced runtime metadata for websites, offline sitelets, and services (the default `noexpressions` mode) to what the runtime reads: class addresses with the compiled form of static methods, anonymous record shapes (remoting), and the part of the dependency graph that leads to resources. On the UI test sites, this reduced the metadata to a fifth of its previous size (218 KB to 43 KB) and made it decode about twice as fast at startup. The `full`, `inlines`, and `notinlines` modes remained unchanged.
* #1614 Moved WebSharper output into a `<AssemblyName>.websharper` sidecar file next to the assembly, containing metadata, generated JavaScript/TypeScript code, source maps, and sources. This left library assemblies exactly as fsc/csc wrote them and avoided the assembly rewrite (about 0.5 s on WebSharper.Tests). Website, bundle, offline, and service projects still embedded their runtime metadata.
* #1615 Implemented incremental compilation:
  * Restored reference assembly production for WebSharper projects (`ProduceReferenceAssembly` defaults to true, including for netstandard2.0), so implementation-only changes to a library no longer recompiled projects that used it. The WebSharper.FSharp and WebSharper.CSharp packages set this default in a `.props` file because the .NET SDK set it to false before importing package `.targets` files.
  * Cached the compilation actions produced while reading each F# source file into WebSharper's representation in the booster (wsfscservice) for the last 20 compiled projects, and replayed them instead of reading the files again. The cache reread a file if it or an earlier file changed by content, or if the compiler options, a reference assembly (by module version ID), WebSharper's view of a reference (its stamp or sidecar), or the project's assembly attributes changed. A rebuild that changed only WebSharper inputs therefore read no files, while an edit reread only the edited file and later files. A short pass over types, annotations, and proxies still ran for every file.
    * Added `WebSharperReadCache=false` (an environment variable of the booster) to turn the cache off, `WebSharperReadCacheProjects` to set how many projects were kept, and `WebSharperReadCacheCheck=true` to reread replayed files, translate both versions, and report a warning if the metadata, errors, or warnings differed.
    * Standalone compilations (wsfsc without the booster) did not cache source reads.

## Fixes

* #1600 Fixed C# language issues:
  * Preserved local functions, ordinary loop jumps, and `finally` semantics when lowering C# labeled control flow.
  * Resolved inherited C# interface members when translating implementations, including enumerator `MoveNext` and `Dispose` methods.

## Breaking changes

* #1614 Changed the compiler to read WebSharper information for references only from their sidecar files. Assemblies built by WebSharper were marked with `[assembly: AssemblyMetadata("WebSharper.Sidecar", "1")]`, and a marked reference without its sidecar, or with a sidecar written for another build of it, produced an error naming the file. The WebSharper targets added the marker to the generated assembly info, or to a generated source file for projects with `GenerateAssemblyInfo` set to false; `WebSharperSidecarMarker=False` disabled it. A reference with WebSharper 10 metadata embedded and no sidecar was reported as needing a WebSharper 11 build.
  * Required `paket pack` templates to include a line for each library in the `files` section, for example `../MyLib/bin/Release/netstandard2.0/MyLib.websharper ==> lib/netstandard2.0`.
  * Limited sidecar use to compile-time references. A copied library DLL in another project's output folder had no sidecar, so compiling against it required a reference to the library project or package.
* #1612 Changed HTTP methods in `WebSharper.Sitelets`:
  * Added a `Query` case to `Http.Method`, so matches listing every case needed one for `Query`. The `QUERY` request had previously used `Custom "QUERY"`.
  * Replaced `UrlHelpers.(|DELETE|GET|OPTIONS|POST|PUT|TRACE|SPECIAL|)` with a partial active pattern for each method: `(|GET|_|)`, `(|POST|_|)`, `(|PUT|_|)`, `(|DELETE|_|)`, `(|OPTIONS|_|)`, `(|TRACE|_|)`, `(|QUERY|_|)`, `(|HEAD|_|)`, and `(|CONNECT|_|)`. Each pattern also matched a `Custom` method with its name and returned `unit option` instead of the parameters and URL, so it composed with `&` and the new request patterns (`PATH`, `PARAM`, `FORM`). For example, `| GET (_, SPLIT_BY '/' ["blog"; INT id]) ->` became `| GET & PATH ["blog"; INT id] ->`; `req.Get.ToList()`, `req.Post.ToList()`, and `req.Uri` still gave the parameters and URL. Replaced `(|SPECIAL|_|)` with `(|CUSTOM|_|)`, which matched only methods not recognized by the others and returned the method name. Matches using these patterns required a final `| _ ->` case.
  * Changed the `UrlHelpers` number patterns (`INT`, `UINT`, `INT64`, `UINT64`, `INT16`, `UINT16`, `INT8`, `UINT8`, `SBYTE`, `BYTE`, `FLOAT`) to parse with invariant culture instead of the server's current culture, and to reject whitespace and thousands separators. Unsigned types rejected a sign, and `FLOAT` accepted a decimal point and an exponent.
* #580 Changed the metadata API and runtime metadata:
  * Replaced `WebSharper.Core.Metadata.IO` with `WebSharper.Core.MetadataIO` and removed `WebSharper.Core.Binary`.
  * Removed instance members, constructors, fields, base classes, and custom type information (other than anonymous records) from classes in the default runtime metadata, and removed dependency graph nodes that led to no resources. Runtime code that needed this information had to use `"runtimeMetadata": "full"` (or `inlines`/`notinlines`).
* Updated compiler APIs:
  * Added `JavaScriptPackager.entryPointBundles` to provide the prebundles for separate packaging, and changed `packageEntryPoint` to return an array. Added `Graph.GetResourceTrimmedData` and `Info.DiscardNotRuntimeClassInfo`. Changed `FrontEnd.WriteDependencies` to accept the files of executed references (`FrontEnd.ExecutedReferences`, from the new `AssemblyResolver.LoadedFiles`), and changed `WebSharper.Compiler.FSharp.Compile.RunFSharpSourceGeneration` to also return the files it loaded. Extended `FrontEnd.WriteDependencies` to accept the files of F# source generators and whether the project could translate without compiling (`WsConfig.CanTranslateOnly`), and added `WsConfig.TranslateOnly`. `Compilation.StartRecording`, `StopRecording`, and `Replay` recorded and replayed what was added to a compilation (`CompilationAction`); added `AddGraphNode`, `AddGraphEdge`, and `AddRequiredFeature` and used them in the F# reader instead of changing `Graph` and creating feature objects itself. Changed `ProjectReader.transformAssemblyWith` to accept a `ReadCache.Context`, and added `MetadataIO.ContentHash`.
  * Replaced `Assembly.Raw` (the Mono.Cecil definition) with `Assembly.Image` (System.Reflection.Metadata) and added `TryGetResource`. Changed `Reflector.TransformAssembly` and `FrontEnd.ModifyWIGAssembly` to accept a `PEMetadata.PEAssembly`, and removed the unused `Reflector.TransformWSAssembly` (for assemblies of the old WebSharper.TypeScript). Removed `LoaderUtility.Resolver`. Moved WIG's `CompiledAssembly` to `WebSharper.Compiler.InterfaceGenerator`; its `Save` method wrote metadata and web resources to the sidecar, and its `AddWebResources`, `Assembly`, and `WebSharperMetadata` members were removed. Changed `FrontEnd.ModifyWIGAssembly` to accept the web resources to hash. Removed WIG `CompilerOptions.Kind`, `ProjectDir`, and `CompilationKind` (WIG only generated libraries). Moved `StubAssembly`'s PE writing (.snk signing, deterministic module ID, and Win32 resources) into the new `PEWriter` module. Moved `CommandTools.RunInterfaceGenerator` to `WebSharper.Compiler.FSharp.Compile` and `CommandTools.LoadInterfaceGeneratorAssembly` to `WebSharper.InterfaceGenerator.ExtensionAssembly.Load` (in `WebSharper.Compiler.InterfaceGenerator`), so `WebSharper.Compiler`, wscsc, and the C# analyzer no longer referenced `WebSharper.InterfaceGenerator`.
  * Removed `FrontEnd.ModifyAssembly`, `ModifyCecilAssembly`, `AssemblyChangeStamp`, `EraseAssemblyContents`, `AddExtraAssemblyReferences`, `Assembly.Write`, and `Assembly.RawBytes`. Changed `FrontEnd.CreateOutput` to return the generated resources, the runtime metadata to embed, and the sidecar entries; changed `HandleExtraFiles` to return the extra.files to store as web resources.
