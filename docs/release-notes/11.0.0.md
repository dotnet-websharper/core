## Features

* #1601 Add .NET 11 as a target framework option and the default for all project templates.
  * Add the .NET 11 `MemoryExtensions.Min` and `Max` span overloads, which are now selected for array extension calls.
  * Support `ReadOnlySpan<T>.ToArray` in collection builder methods.
* #1600 Translate C# 15 collection expression arguments, union declarations and patterns, extension indexers, and labeled `break` and `continue`.
  * Added the `Enumerable.Chunk` proxy using the shared `Seq.chunkBySize` implementation.
* #1599 Support FSharp.Core `partitionWith` for arrays, lists, sets, and parallel arrays in JavaScript, with tests for record spreads, extension operators, and all-fields record constructors.
  * Preserve resolved F# extension operators in generic inline calls.

## Performance

* #580 New WebSharper metadata format and serializer.
  * Metadata is read and written by generated F# code instead of reflection: no encoder derivation at startup, no boxing, and no per-node `obj[]`.
  * Strings, type definitions, methods and constructors are written once and referenced by index, integers are variable-length, and member expressions are length-prefixed blocks.
  * The payload is compressed with Deflate at the Fastest level instead of gzip at its default level.
  * Metadata is split into sections (strings, type tables, main info, inline expressions, other expressions, dependency graph), compressed separately. Compiling a library (or proxy) project without dead code elimination or an output folder reads only what translation needs from references: non-inline code and dependency graphs are not decompressed or decoded. Web worker bundles read the rest when needed. On the core build this reads reference metadata about 4 times faster, and the booster caches less.
  * The compiler logs separate stages for loading referenced assemblies, reading and merging reference metadata, encoding and compressing metadata, and the Cecil assembly write.

* #1560 WebSharper output goes into a `<AssemblyName>.websharper` sidecar file next to the assembly: metadata, generated JavaScript/TypeScript code, source maps and sources. Library assemblies stay exactly as fsc/csc wrote them unless extra.files or web worker bundles are embedded, which avoids the assembly rewrite (about 0.5 s on WebSharper.Tests). Website, bundle, offline and service projects still embed their runtime metadata.
  * MSBuild copies the sidecar to the output folder, copies sidecars of references (`.websharper` is in `AllowedReferenceRelatedFileExtensions`) and packs it with `dotnet pack`.
  * The WebSharper build script adds sidecars to Paket templates when packing.
  * The booster cache is invalidated by sidecar changes too.
  * extra.files of libraries and web worker bundles are web resources in the sidecar instead of embedded resources with `WebResource` attributes, so no library assembly is rewritten. Websites unpack them as before, and `BaseResource` finds them at runtime through the resource hashes in the runtime metadata (`Resources.IsExternalWebResource`).
  * Website, bundle and offline assemblies no longer get extra assembly references to WebSharper libraries: runtime metadata is merged into them, and `deps.json` lists the libraries for loading.
* WebSharper projects produce reference assemblies again (`ProduceReferenceAssembly` defaults to true, also for netstandard2.0), so a change that only affects a library's implementation does not recompile the projects using it.
  * The compiler writes a `<AssemblyName>.websharper.stamp` file, a hash of what compiling a library against this one reads (types, addresses and inline code), only rewritten when that changes.
  * Each compilation lists the reference files it read in `obj/<AssemblyName>.websharper.deps`: stamps of libraries for library projects, full sidecars for website, bundle and dead code eliminated projects or ones with web worker bundles. MSBuild adds them to the compilation inputs.
  * WebSharper reads references from the implementation assemblies next to `ref`/`refint` reference assemblies, as macros and generators run code from them.
  * For WIG, Proxy and BundleOnly projects, the reference assembly is replaced by the final assembly WebSharper writes.
  * wscsc compiles again when the assembly was written after the last WebSharper compilation finished, also when it has the same module version id.

## Breaking changes

* #1560 The compiler reads WebSharper information of references only from their sidecar files. Assemblies built by WebSharper are marked with `[assembly: AssemblyMetadata("WebSharper.Sidecar", "1")]`, and a marked reference without its sidecar, or with a sidecar written for another build of it, is an error naming the file.
  * Packages built with `paket pack` without the WebSharper build script need a line for each library in the `files` section of the template, for example `../MyLib/bin/Release/netstandard2.0/MyLib.websharper ==> lib/netstandard2.0`.
  * Deployments copying `*.dll` selectively don't need sidecars at runtime, only for compiling against a library.

* #580 WebSharper 11 can't read metadata written by WebSharper 10 or earlier: recompile every WebSharper library with WebSharper 11. Reading an old library reports that it needs recompiling.
  * `WebSharper.Core.Metadata.IO` is replaced by `WebSharper.Core.MetadataIO`, and `WebSharper.Core.Binary` is removed.

## Fixes

* #1600 C# language fixes:
  * Preserve local functions, ordinary loop jumps, and `finally` semantics when lowering C# labeled control flow.
  * Resolve inherited C# interface members when translating implementations, including enumerator `MoveNext` and `Dispose` methods.
