## Features

* #1601 Add .NET 11 as a target framework option and the default for all project templates.
  * Add the .NET 11 `MemoryExtensions.Min` and `Max` span overloads, which are now selected for array extension calls.
  * Support `ReadOnlySpan<T>.ToArray` in collection builder methods.
* #1600 Translate C# 15 collection expression arguments, union declarations and patterns, extension indexers, and labeled `break` and `continue`.
  * Added the `Enumerable.Chunk` proxy using the shared `Seq.chunkBySize` implementation.
* #1599 Support FSharp.Core `partitionWith` for arrays, lists, sets, and parallel arrays in JavaScript, with tests for record spreads, extension operators, and all-fields record constructors.
  * Preserve resolved F# extension operators in generic inline calls.

## Performance

* #580 New WebSharper metadata format and serializer.
  * Metadata is read and written by generated F# code instead of reflection: no encoder derivation at startup, no boxing, and no per-node `obj[]`.
  * Strings, type definitions, methods and constructors are written once and referenced by index, integers are variable-length, and member expressions are length-prefixed blocks.
  * The payload is compressed with Deflate at the Fastest level instead of gzip at its default level.
  * Metadata is split into sections (strings, type tables, main info, inline expressions, other expressions, dependency graph), compressed separately. Compiling a library (or proxy) project without dead code elimination or an output folder reads only what translation needs from references: non-inline code and dependency graphs are not decompressed or decoded. Web worker bundles read the rest when needed. On the core build this reads reference metadata about 4 times faster, and the booster caches less.
  * The compiler logs separate stages for loading referenced assemblies, reading and merging reference metadata, encoding and compressing metadata, and the Cecil assembly write.

## Breaking changes

* #580 WebSharper 11 can't read metadata written by WebSharper 10 or earlier: recompile every WebSharper library with WebSharper 11. Reading an old library reports that it needs recompiling.
  * `WebSharper.Core.Metadata.IO` is replaced by `WebSharper.Core.MetadataIO`, and `WebSharper.Core.Binary` is removed.

## Fixes

* #1600 C# language fixes:
  * Preserve local functions, ordinary loop jumps, and `finally` semantics when lowering C# labeled control flow.
  * Resolve inherited C# interface members when translating implementations, including enumerator `MoveNext` and `Dispose` methods.
