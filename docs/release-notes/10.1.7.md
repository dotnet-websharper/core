This is a minor release of WebSharper 10.1. NuGet version `10.1.7`.

Templates for .NET Core SDK: `dotnet new install WebSharper.Templates@10.1.7`

## Enhancements
* #1587 Added a `localMetaprogramming` wsconfig setting (default `false`) that gates the use of macros/generators defined in the same project that is being compiled. This is a **breaking change**: a project that both defines and applies a macro/generator in the same assembly must add `"localMetaprogramming": true` to its `wsconfig.json` (or set the `WebSharperLocalMetaprogramming` MSBuild property) to keep compiling; otherwise the compiler now gives a directed error instead of silently loading the just-emitted assembly with Reflection. Macros/generators used from a referenced assembly are unaffected by the gating itself. This is a first step towards allowing WebSharper (F#) translation to run in parallel with the .NET compilation.
* The `Compilation.UseLocalMacros` property is now deprecated and merged into `LocalMetaprogramming` (same backing value). As a consequence, a macro/generator load failure for a **referenced**-assembly macro/generator (e.g. a broken binding) is now a warning with `Undefined` fallback by default, instead of a compile error, unless `"localMetaprogramming": true` is set.
