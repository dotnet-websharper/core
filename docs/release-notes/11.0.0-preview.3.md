This is a preview release of WebSharper 11.0.

## Performance

* #1697 Emitted the .NET assembly in parallel with the WebSharper type check again for projects using the WebSharper.UI templating type provider, which is almost every WebSharper.UI application. Since #1687 any referenced type provider delayed it until after the type check. Type providers that are safe to run from two type checks at the same time can now say so: the compiler recognizes `WebSharper.ThreadSafeTypeProviderAttribute` on the type provider's assembly by its full name, so a type provider can declare its own copy instead of referencing WebSharper. WebSharper.UI marks its templating type provider.
  * The `WebSharperThreadSafeTypeProviders` MSBuild property (`threadSafeTypeProviders` in `wsconfig.json`, `--threadsafetypeprovider:<name>`) treats other type providers as thread-safe, by assembly name.
  * `WebSharperSerializeTypeProviders=true` (`serializeTypeProviders`, `--serializetypeproviders+`) delays the assembly whenever a type provider is referenced, as since #1687, for a marked type provider that turns out not to be thread-safe.
  * With detailed build output (`-v:d`), the compiler names the type providers that made it wait.
