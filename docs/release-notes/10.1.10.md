This is a minor release of WebSharper 10.1. NuGet version `10.1.10.687`.

Templates for .NET Core SDK: `dotnet new install WebSharper.Templates@10.1.10.687`

## Fixes
* #1613 F# builds on Windows no longer hang in the `WebSharperCompile` step when the WebSharper booster (`wsfscservice`) is not running yet and the WebSharper compiler runs on .NET 11. The compiler runs on the newest .NET runtime installed, so installing .NET 11 was enough to trigger it with any version since 6.1.4. The build had to start the booster, and on .NET 11 the booster kept the output of the `WebSharperCompile` task open, so MSBuild waited for it after the compilation was done. With MSBuild before 18.6 (Visual Studio 2022, .NET SDK 8 and 9, early .NET 10 SDKs) the build hung until the booster was stopped. With later MSBuild versions it continued after a 30 second delay. The booster is now started without access to the build's output, and without a console window. To work around this in earlier versions, start the booster before building, set `WebSharperStandalone` to `true` to build without it, or set the environment variable `DOTNET_ROLL_FORWARD=LatestPatch` to keep the compiler off .NET 11.
